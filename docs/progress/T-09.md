5. `backend/app/llm/gateway.py`:
   - Core `LLMGateway` client implementation:
     - Task aliases: `kh-extract-image`, `kh-extract-text`, `kh-agent`, `kh-parse`.
     - Alias timeouts per SPEC §6: `kh-extract-image`: 20s, `kh-extract-text`: 20s, `kh-agent`: 8s, `kh-parse`: 5s.
     - `LLMUnavailable` typed exception inheriting from HTTPException(503).

     - Thinking text ignored/disabled (`chat_template_kwargs.enable_thinking=false` configured at gateway; direct json parsing).
     - Records every call to database table `llm_calls` with task, provider "nvidia", model, latency_ms, tokens, success, failure.

6. `backend/app/api/health.py`:
   - Update `check_llm()` to check LLMGateway status: returns `"ok"` when online/available, `"degraded"` when in stub mode, degraded mode or recent failures, `"down"` if gateway unreachable.
7. `backend/tests/fixtures/llm/`:

   - Unit tests covering:
     - Stub mode extraction returns valid `ExtractedReceipt`.
     - Invalid JSON response triggers repair retry.
     - Successful repair after 1 retry.
     - Failed repair after 1 retry raises validation failure.
     - Network timeout maps to `LLMUnavailable`.
     - Gateway 5xx/connection error maps to `LLMUnavailable`.
     - DB logging writes `llm_calls` rows with correct fields (`provider="nvidia"`, latency, tokens, etc.).
     - Aliases mapping to proper timeouts without vendor model names.
9. `backend/tests/test_health.py`:
   - Test `/v1/healthz` reporting `"llm": "degraded"` or `"ok"` under respective conditions.

## Decisions
- Tasks communicate exclusively via task aliases defined in `gateway/litellm.config.yaml` (`kh-extract-image`, `kh-extract-text`, `kh-agent`, `kh-parse`).
- In stub mode (`LLM_MODE=stub`), responses are served from `tests/fixtures/llm/<alias>/` to ensure 0 external network traffic in test suites.
- When live LLM is requested, timeout limits are enforced at client level matching SPEC §6: 20s for extraction, 8s for agent, 5s for parse.
- Any unrecoverable LLM failure raises `LLMUnavailable`, allowing downstream workflows to enter degraded mode.
